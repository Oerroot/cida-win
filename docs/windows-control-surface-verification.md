# 按钮圆角边缘修复 · v0.2.0-rc.5

2026-10-10；基线 `b2665f02df55b9923de381fc8bb10da64c6ece2d`。用户确认问题出现在全部按钮，包括主面板翻译、摘要等共用模板的控件。本次继续已授权的 Windows 体验修复。

## 可复现原因

此前的模板使用 WPF Border 分别绘制圆角描边和内缩底色。它们在内缘各自抗锯齿，圆角处覆盖不连续。即使描边和底色完全同色，仍然可见来自父背景的细小色带；不能仅靠布局取整消除，更不能把它归因于圆角半径太大。

依据 [WPF Border 源码](https://github.com/dotnet/wpf/blob/main/src/Microsoft.DotNet.Wpf/src/PresentationFramework/System/Windows/Controls/Border.cs)，均匀圆角路径先画描边，再画内缩底色。受控像素检查在固定 6 DIP 半径下复现了该现象；同一行从外部进入同色按钮时，像素接近底色后又偏离，形成第二圈色带。

## 实现

- 新增共享 ControlSurface，底色覆盖完整外轮廓及描边下方，再叠加描边。描边与底色同色时只绘制底色；保留原半径及外轮廓。均匀边框按真实 WPF DPI 对齐厚度，描边中心内缩半个厚度；非均匀边框/圆角沿用 WPF Border。
- 普通、主操作、动作选择按钮统一采用该表面；折叠标题、下拉按钮、输入框与密码框同步使用。内容测量、Padding、模板部件及交互保持原机制。
- 按压、禁用改用主题颜色，移除这些控件的整体透明度处理；键盘按钮焦点改用匹配圆角的轮廓。高对比度仍使用 Windows 系统颜色。

## 验证与边界

VisualChecks 增加真正的像素回归检查，比较原 Border 与生产 ControlSurface。浅色/深色各检查 1、1.25、1.5、2 倍受控栅格输出；旧实现分别发现 2、10、16、16 处圆角色带回退，新实现均为 0。此指标只测同色圆角的覆盖连续性，不能代替主观设计验收或真实 OS DPI 切换。输出 `control-surface-metrics.json` 和 16 张表面对照，加上原有 28 张产品视图。

`dotnet run --project tests/Cida.VisualChecks -c Release -- --check-control-surfaces` 单独执行该回归，不打开产品窗口或使用剪贴板；已加入 PR/主分支及 tag 发布 CI，检查失败会阻止打包。全视图受控渲染使用 `--render-suite`。
