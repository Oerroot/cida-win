# 主面板标题栏拖动修复 · v0.2.0-rc.6

2026-10-10，基线 `66bc7a22f78ebca63ee153902c82e92af1c257d5`。

rc.5 的 `WindowChrome.CaptionHeight` 为 0，手工 `DragMove()` 只绑定到带 `28,18,20,0` 外边距的标题内层。用户确认图标、文字能拖动，顶部空白和最上沿不能拖动；这些位置恰好在事件区域之外。

本次将完整标题栏交给 Windows 原生拖动。CaptionHeight 根据标题栏实际底边计算，包含顶部和左右留白；设置、关闭按钮单独保留客户区命中。移除内层手工拖动事件，原文和结果区域仍用于编辑、选取。

已完成 Release 构建。`--check-panel-chrome` 查询真实 HWND 的 `WM_NCHITTEST`，覆盖顶沿、顶部留白、左右留白、图标、文字、标题空白、按钮间隙，以及设置、关闭、原文、执行、结果等客户区。浅/深色、800/340 DIP 宽度共 60 个位置通过，实际执行桌面 DPI 为 96；该检查已加入构建及发布 CI。

实际鼠标验收被用户 Escape 中止，没有声称该项已完成。独立验收工具新增正常失焦隐藏模式，仅为自动化窗口发现显示任务栏按钮，不修改产品窗口的任务栏设置。没有重跑上轮全部视觉、剪贴板及外部应用测试。

交付 rc.6 未签名候选安装包、便携包及 SHA256 校验文件，保留既有版本。
