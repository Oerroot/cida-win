# Windows 界面细节修复验证 · v0.2.0-rc.3

2026-10-08；Windows 11 x64，本机 .NET SDK 10.0.401。基线 `4e74d5a2f62a9de3ed1f96e03570cd383c2d49e6`。本次针对用户指出的四处问题修复；上一轮完整体验验证保留在 [rc.2 记录](windows-experience-verification.md)。

## 原因与修复

| 问题 | 源码原因 | 修复与本机证据 |
|---|---|---|
| 托盘、设置标题栏图标模糊 | 托盘固定加载 32 px 再交给系统缩小，复杂衬线字标不适合 16 px | 为 16/20/24/28/32/40 px 单独按像素网格生成简化字标，48 px 以上保留完整字标；ICO 含 10 个独立 PNG 帧。按任务栏 DPI 和系统小图标尺寸选帧，本机实际返回 16×16。设置窗口显式使用多尺寸 ICO |
| 主面板没有图标、按钮像文本 | 标题未放置品牌图片，默认按钮透明且无边框 | 主标题补 24 px 字标和随主题文字；设置/关闭加入图形与文字，统一可见边界、悬停、按压、禁用和键盘焦点；动作、复制等按钮共享样式 |
| 模型表单不齐、下拉箭头粗糙 | 内容宿主重复内边距，不同控件没有统一高度；默认下拉样式混入产品界面 | 单行文本框、密码框、下拉框统一 40 DIP，去除重复内容偏移；同一行实际 Y 坐标一致；改为细线箭头，展开旋转，弹出列表宽度跟随字段 |
| 托盘右键菜单粗糙 | 直接使用未主题化的 WinForms 默认菜单 | 保留原生菜单焦点与关闭行为，统一字体、行高、图形、分隔线、右侧快捷键和浅深色；按菜单 DeviceDpi 计算尺寸。使用与生产相同的工厂生成浅深色截图，真实窗口操作“设置”和“退出辞达”成功 |

上一轮验收集中在主视图和功能流程，没有充分覆盖托盘小图标、系统标题栏和原生菜单，也没有对表单同行尺寸建立断言。本次视觉工具补充这些检查，表单不齐会直接失败。

## 已运行检查

```powershell
dotnet build windows -c Release
dotnet test tests/Cida.Core.Tests -c Release
$env:CIDA_DESKTOP_TESTS = '1'
dotnet test tests/Cida.Windows.Tests -c Release
Remove-Item Env:\CIDA_DESKTOP_TESTS
dotnet run --project tests/Cida.VisualChecks -- --render-suite
pwsh -File scripts/package.ps1 -Version 0.2.0-rc.3
```

Release 构建 0 警告、0 错误；Core **96/96**，交互桌面 Windows **5/5**。Windows 测试使用独立 STA、自有编辑器及本地模拟服务，覆盖选择/替换/一次撤销、剪贴板保护、UIA 段落、离线中英文 OCR 等。为避免共享桌面的焦点和 TSF 状态干扰，受控测试面板不自动隐藏，测试编辑器关闭 IME；这不代替真实 IME 组合输入验收。CI 未启用交互桌面时为 **4 通过、1 跳过**。

回归还暴露剪贴板写入后采样序号过早：Windows 关闭剪贴板时会合成文本格式、推进序号，导致合法恢复被拒绝。改为关闭后采样；恢复仍同时检查预期序号及本应用所有者，其他程序的新复制不会被覆盖。测试清理也区分自有写入与来源应用的复制，保留其他程序写入。

视觉工具输出 **28 张**图片：26 张真实 WPF 受控渲染及 2 张生产原生菜单渲染。浅深色模型页均测得协议、模型、密钥操作与密码框高度 40 DIP，同行 Y 坐标相等。实际标题栏、小图标、下拉打开/选择/关闭、菜单设置/退出已在本机窗口检查。
